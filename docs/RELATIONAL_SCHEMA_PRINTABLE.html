1. Entity Classification Summary (Strong vs. Weak vs. Associative)

Classification Relation / Table Primary Key Identifying Owner Entity Discriminator / Partial Key Cascade Semantics Relational Justification
Strong Entity app_user user_id None (Independent) — — Root authentication authority. Surrogate key user_id, candidate key email.
Strong Entity department dept_id None (Independent) — — Academic branches directory. Independent candidate key: code (CSE, AIML, etc.).
Strong Entity company company_id None (Independent) — — Corporate employer entities. Independent candidate key: name.
Strong Entity skill skill_id None (Independent) — — Standard technical taxonomy. Independent candidate key: name.
Strong Entity policy_config policy_id None (Independent) — — Placement governance rule set. Candidate key: policy_key.
Strong Entity audit_log log_id None (Independent) — — Append-only compliance audit trail. Independent surrogate key log_id.
Strong Subtype student student_id app_user (1:1 Specialization) — ON DELETE CASCADE Student profile entity with domain candidate key usn and user_id.
Strong Subtype recruiter recruiter_id app_user (1:1 Specialization) — ON DELETE CASCADE Corporate recruiter profile entity with candidate key user_id.
Strong Entity internship_posting posting_id company (Owner) — ON DELETE RESTRICT Job vacancy posting with independent surrogate key posting_id.
Weak Entity application_stage_history history_id application changed_at ON DELETE CASCADE Existence-Dependent Weak Entity: Stage transitions have no existential meaning without parent application. Guarded by trg_stage_history_immutable.
Weak Entity interview interview_id application round_no ON DELETE CASCADE Subordinate Weak Entity: Identified per application via discriminator round_no with integrity constraint UNIQUE(application_id, round_no).
Dependent Entity offer offer_id application — ON DELETE CASCADE Dependent 1:1 Entity: Terminal contractual compensation record identified with parent application (UNIQUE(application_id)).
Associative Entity student_skill (student_id, skill_id) student, skill Composite PK CASCADE / RESTRICT Resolves M:N relationship between Student and Skill. Non-key attribute: proficiency_level.
Associative Entity posting_skill (posting_id, skill_id) internship_posting, skill Composite PK CASCADE / CASCADE Resolves M:N relationship between Internship Posting and Skill requirements. Non-key attribute: min_level.
Associative Entity posting_eligible_dept (posting_id, dept_id) internship_posting, department Composite PK CASCADE / RESTRICT Resolves M:N department eligibility whitelist for job postings.
Associative Entity interview_panelist (interview_id, recruiter_id) interview, recruiter Composite PK CASCADE / RESTRICT Resolves M:N relationship between Interview rounds and attending interviewers.
Associative Entity application application_id student, internship_posting (student_id, posting_id) CASCADE / CASCADE Resolves M:N relationship between Candidates and Openings with lifecycle attributes (current_stage, match_score).

2. Formal Relational Schema Definitions (BCNF Normalized)

1. app_user

Strong Entity
app_user(user_id, email, password_hash, role, is_active, created_at, updated_at)
Candidate Keys: {user_id}, {email} | Normal Form: BCNF

2. department

Strong Entity
department(dept_id, name, code, created_at)
Candidate Keys: {dept_id}, {code} | Normal Form: BCNF

3. student

Strong Entity (Subtype of app_user)
student(student_id, user_id*, usn, full_name, dept_id*, cgpa, year_of_study, grad_year, phone, bio, profile_embedding, created_at, updated_at)
Candidate Keys: {student_id}, {usn}, {user_id} | FK: user_id ➔ app_user(user_id) ON DELETE CASCADE, dept_id ➔ department(dept_id) | Normal Form: BCNF

4. skill

Strong Entity
skill(skill_id, name, category, created_at)
Candidate Keys: {skill_id}, {name} | Normal Form: BCNF

5. student_skill

Associative Entity
student_skill(student_id*, skill_id*, proficiency_level, created_at)
Primary Key: {student_id, skill_id} | FK: student_id ➔ student(student_id), skill_id ➔ skill(skill_id) | Normal Form: BCNF

6. company

Strong Entity
company(company_id, name, website, industry, size_range, verified, verified_by*, created_at)
Candidate Keys: {company_id}, {name} | FK: verified_by ➔ app_user(user_id) ON DELETE SET NULL | Normal Form: BCNF

7. recruiter

Strong Entity (Subtype of app_user)
recruiter(recruiter_id, user_id*, company_id*, full_name, designation, phone, created_at)
Candidate Keys: {recruiter_id}, {user_id} | FK: user_id ➔ app_user(user_id), company_id ➔ company(company_id) | Normal Form: BCNF

8. internship_posting

Strong Entity
internship_posting(posting_id, company_id*, created_by*, title, description, location, stipend, openings, filled, min_cgpa, deadline, mode, status, embedding, search_tsv, created_at, updated_at)
Primary Key: {posting_id} | FK: company_id ➔ company(company_id), created_by ➔ recruiter(recruiter_id) | Normal Form: BCNF

9. posting_eligible_dept

Associative Entity
posting_eligible_dept(posting_id*, dept_id*)
Primary Key: {posting_id, dept_id} | FK: posting_id ➔ internship_posting(posting_id), dept_id ➔ department(dept_id) | Normal Form: BCNF

10. posting_skill

Associative Entity
posting_skill(posting_id*, skill_id*, min_level)
Primary Key: {posting_id, skill_id} | FK: posting_id ➔ internship_posting(posting_id), skill_id ➔ skill(skill_id) | Normal Form: BCNF

11. application

Associative Entity with Lifecycle State
application(application_id, student_id*, posting_id*, applied_at, current_stage, match_score, withdrawn_at, created_at, updated_at)
Candidate Keys: {application_id}, {student_id, posting_id} | FK: student_id ➔ student(student_id), posting_id ➔ internship_posting(posting_id) | Normal Form: BCNF

12. application_stage_history

Weak Entity (Identifying Owner: application)
application_stage_history(history_id, application_id*, from_stage, to_stage, changed_by*, reason, changed_at)
Primary Key: {history_id} | FK: application_id ➔ application(application_id) ON DELETE CASCADE | Normal Form: BCNF

13. interview

Weak Entity (Identifying Owner: application)
interview(interview_id, application_id*, round_no, scheduled_at, duration_min, mode, link_or_room, status, created_at)
Primary Key: {interview_id} | Candidate Key: {application_id, round_no} | FK: application_id ➔ application(application_id) ON DELETE CASCADE | Normal Form: BCNF

14. interview_panelist

Associative Entity
interview_panelist(interview_id*, recruiter_id*)
Primary Key: {interview_id, recruiter_id} | FK: interview_id ➔ interview(interview_id), recruiter_id ➔ recruiter(recruiter_id) | Normal Form: BCNF

15. offer

Dependent Entity (1:1 with application)
offer(offer_id, application_id*, stipend, start_date, expires_at, status, created_at, responded_at)
Candidate Keys: {offer_id}, {application_id} | FK: application_id ➔ application(application_id) ON DELETE CASCADE | Normal Form: BCNF

16. policy_config

Strong Entity
policy_config(policy_id, policy_key, policy_value, description, updated_by*, updated_at)
Candidate Keys: {policy_id}, {policy_key} | FK: updated_by ➔ app_user(user_id) | Normal Form: BCNF

17. audit_log

Strong Entity
audit_log(log_id, user_id*, action, entity_name, entity_id, details, ip_address, created_at)
Primary Key: {log_id} | FK: user_id ➔ app_user(user_id) | Normal Form: BCNF
